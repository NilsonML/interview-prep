# interview-prep

[![CI](https://github.com/NilsonML/interview-prep/actions/workflows/ci.yml/badge.svg)](https://github.com/NilsonML/interview-prep/actions/workflows/ci.yml)

Практика к собеседованию на ML Engineer: структуры данных с нуля, алгоритмы по паттернам,
Python изнутри, ML без библиотек и вопросы с ответами. **109 задач, 116 тестов.**

Каждая задача — заготовка: сигнатура, условие, цель по сложности и вопрос «подумай до кода».
Решение пишешь ты, тесты проверяют. Нерешённые задачи pytest помечает как `skipped`,
поэтому прогресс виден сразу:

```
=========================== Прогресс ===========================
Структуры данных             [######--------------]   5/18
Алгоритмы: паттерны 1-5      [###-----------------]   5/34
...
```

## Как работать

```bash
git clone https://github.com/NilsonML/interview-prep && cd interview-prep
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt

pytest                                       # всё + таблица прогресса
pytest tests/test_algorithms_arrays.py -k two_sum      # одна задача
```

**Цикл одной задачи**

1. Прочитай docstring. Ответь на «Подумай» **до** кода. Назови наивное решение и его сложность.
2. **25–40 минут честной попытки.** Не получается — подсказки по лестнице: намёк на идею →
   подход → псевдокод. Готовое решение — в самом крайнем случае.
3. `pytest -k имя_задачи`. Упал стресс-тест — выпиши вход, на котором упало, и разбери руками.
4. Проговори вслух: идея, сложность по времени и памяти, краевые случаи.
5. Запиши в [JOURNAL.md](JOURNAL.md). Через 3 и 7 дней реши задачу заново с пустого файла.

**Эталонные решения** лежат в ветке [`solutions`](../../tree/solutions) с комментариями
«почему так». Смотри их только **после** своего решения: сравни подходы, не копируй.

**Git-процесс как в команде:** ветка на неделю (`git checkout -b week-01`), коммит на задачу
(`feat(p01): two_sum O(n) via dict`), pull request в `main`. CI проверит линтер и тесты,
а я сделаю code review в PR.

Ритм: 2 дня алгоритмов, 2 дня Python / ML, 1 день повторения и вопросов из `questions/`.

| 2 | — | p02 два указателя, p03 окно | `decorators` | Python 9–15, алгоритмы 1–3 |
| 3 | `stack_queue` | p04 стек, p05 бинарный поиск | `context_managers`, `collections_tasks` | Python 16–25 |

| 7 | `union_find`, `trie` | p09 графы | — | алгоритмы 9–10 |

После каждых двух недель — повтори все решённые задачи с нуля на время.
Параллельно: 2–3 задачи в неделю на LeetCode по тому же паттерну, чтобы видеть его в
незнакомой формулировке.

## Как устроен репозиторий

- `conftest.py`: `NotImplementedError` → `skipped` и таблица прогресса в конце `pytest`.
- Тесты проверяют не только примеры, но и краевые случаи и **стресс-тесты** против наивного
  решения на случайных входах. Это главный приём поиска ошибок в границах.
- `ml_basics` сверяется с `sklearn`: твоя реализация должна давать те же числа.
- CI (GitHub Actions): `ruff` + `pytest` на каждый push.
