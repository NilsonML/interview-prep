# interview-prep

[![CI](https://github.com/NilsonML/interview-prep/actions/workflows/ci.yml/badge.svg)](https://github.com/NilsonML/interview-prep/actions/workflows/ci.yml)

Практика к собеседованию на ML Engineer: алгоритмы, структуры данных, Python и ML.
Минимум теории, максимум задач. Каждая тема проходится **пятью разными способами**,
потому что одно и то же знание проверяют по-разному: написать, прочитать, починить, измерить, объяснить.

**174 задачи, 181 тест, 4 лабы.** Нерешённые задачи pytest помечает как `skipped`,
а в конце печатает прогресс:

```
=========================== Прогресс ===========================
Структуры данных             [####----------------]   4/18
Алгоритмы: паттерны 1-5      [####----------------]   7/34
Предскажи результат          [######--------------]  12/42
Почини баг                   [##------------------]   3/23
...
```

## Пять форматов

| Формат | Где | Что делаешь | Какой навык |
|---|---|---|---|
| **Используй** | [`algorithms/`](algorithms) — 64 задачи LeetCode в 11 паттернах | Решаешь задачу готовыми `dict`, `heapq`, `deque` | Узнать паттерн и решить, как на coding-интервью |
| **Загляни внутрь** | [`data_structures/`](data_structures) — 11 структур | Читаешь «как устроено» (схема, аналогия, шаги) и собираешь сам | Объяснить, почему O(1) или O(log n) и когда нет |
| **Предскажи** | [`predict/`](predict) — 42 фрагмента | Не запуская код, пишешь в `ANSWERS`, что он вернёт | Читать код и трассировать состояние в голове |
| **Почини** | [`bugfix/`](bugfix) — 23 баг-репорта | Воспроизводишь баг, исправляешь, ставишь `FIXED = True` | Отладка: границы, утечки данных, ловушки Python |
| **Измерь** | [`labs/`](labs) — 4 эксперимента | Предсказываешь результат замера, запускаешь, сравниваешь | Чувство реальной сложности и констант |

Плюс Python ([`python_core/`](python_core)), ML на NumPy ([`ml_basics/`](ml_basics)) и
вопросы с ответами под спойлером: [Python](questions/python.md), [алгоритмы](questions/algorithms.md),
[ML](questions/ml.md), [SQL](questions/sql.md).

В каждом модуле наверху короткая шпаргалка: **сигналы в условии** (как узнать паттерн),
идея с аналогией, термины и типичные ошибки. Длинной теории нет: она в задачах.

## Неделя: что и в каком порядке

Порядок внутри темы всегда один: **используй → предскажи → загляни внутрь → почини → измерь**.
Сначала структура работает на тебя в задачах, потом ты видишь её изнутри.

| | Используй | Предскажи | Загляни внутрь | Почини | Python / ML | Лаба |
|---|---|---|---|---|---|---|
| 1 | p01 хеширование | python q01–q06, structures q10 | `hash_map` (рек.), `dynamic_array` (опц.) | `add_tag`, `make_multipliers`, `remove_negatives`, `two_sum` | `generators` | 01, 02 |
| 2 | p02 указатели, p03 окно | python q07–q12, structures q11–q12 | — | `merge_config`, `logged`, `max_profit`, `longest_unique_substring`, `merge_intervals` | `decorators` | — |
| 3 | p04 стек, p05 бинпоиск | python q13–q18, structures q03, q07, q08 | `stack_queue` (обяз.) | `mean_and_max`, `group_by_first_letter`, `binary_search`, `is_valid_brackets` | `context_managers`, `collections_tasks` | 03 |
| 4 | p06 связные списки | — | `linked_list`, `lru_cache` (обяз.) | — | — | — |
| 5 | p07 деревья | structures q06, numpy q01–q04 | `bst` (удаление — опц.) | `precision`, `log_loss` | `ml_basics/metrics` | — |

| 9–10 | p11 динамика | structures q09 | повторение | `coin_change` | `models`: kNN, k-means | — |

**обяз.** — сами структуры спрашивают на интервью как задачи (LeetCode 146, 155, 208, 232).
**рек.** — на интервью ты используешь готовую, но должен объяснить устройство.
**опц.** — по желанию: понять по схеме достаточно.

**Ритм:** 5 дней по 1–2 часа. Пн–Вт — «используй» и «предскажи»; Ср — «загляни внутрь»;
Чт — «почини» и Python / ML; Пт — повторение задач прошлых недель, вопросы из
`questions/`, лаба. Каждые две недели — повтор всех решённых задач с нуля на время.

## Как работать

```bash
git clone https://github.com/NilsonML/interview-prep && cd interview-prep
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pytest                                    # всё + таблица прогресса
pytest -k two_sum                         # одна задача
pytest tests/test_predict.py -k python    # один формат
```

**Задача на «используй» / «загляни внутрь»:** прочитай docstring → ответь на «Подумай» →
назови наивное решение и его сложность → 25–40 минут попытки → `pytest -k имя`.
Застрял — напиши мне «подсказка 1 по имя_задачи». Подсказки идут лесенкой: намёк → подход → псевдокод.

**«Предскажи»:** ответ — в `ANSWERS` того же файла. Код не запускать, это весь смысл.
**«Почини»:** сначала воспроизведи баг, потом исправь и оставь комментарий
`# БАГ: ... ИСПРАВЛЕНИЕ: ...`, потом `FIXED["имя"] = True`.

**После каждой задачи:** строка в [JOURNAL.md](JOURNAL.md). Через 3 и 7 дней — повтор с нуля.

**Эталонные решения** в ветке [`solutions`](../../tree/solutions): ответы с объяснениями,
исправленные баги, реализации с комментариями «почему так». Смотри только после своего решения:
`git show solutions:data_structures/hash_map.py`.

**Git как в команде:** ветка на неделю (`git checkout -b week-01`), коммит на задачу
(`feat(p01): two_sum O(n) via dict`), в конце недели pull request в `main` — я делаю code review.
